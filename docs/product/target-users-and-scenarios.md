## 1. 一句话目标用户

> **经常和 AI 协作做工程工作的个人开发者，以及 2~10 人的小技术团队。**

## 2. 三类核心用户画像

### A. 重度 AI 编程的个人开发者

- 每天与 AI 协作 ≥ 2 小时
- 拥有 Windows 11 / macOS Apple Silicon 桌面机
- 已经用过 Cursor / Cline / Aider / Claude Code 等
- 倾向于**少依赖外部平台**，希望工具能在本机长期可用
- 关注：可控性、可回看性、不被 SaaS 绑死

### B. 拥有固定工作站 + 远程节点的小团队技术负责人

- 团队 2~10 人
- 自己有家里 / 团队的 Linux server 或 NAS
- 希望桌面端作为主控制面，同时接入团队自建 server
- 关注：协作可见性、数据自控、长期成本

### C. 本地优先 / 自托管偏执用户

- 在意数据位置、模型接入自由、长期可迁移性
- 不愿意把工程上下文交给闭源 SaaS
- 可能是独立开发者、咨询顾问、研究者
- 关注：数据归属、可审计性、可迁移性

## 3. 反目标用户（明确不优化）

- 完全不写代码的普通办公用户
- 大型企业合规 / 治理 / 多租户场景
- 只想要"一键完成"的零接管用户
- 仅在浏览器使用、拒绝安装桌面应用的用户

> 这些群体的需求是合理的，但**不在 Cairn 第一阶段的优化目标内**。我们不主动反对，但也不为他们做产品妥协。

## 4. 高价值任务类型（优先支持）

| 任务类型             | 典型场景                               | Cairn 的价值                    |
| -------------------- | -------------------------------------- | ------------------------------- |
| 中等复杂代码改动     | "在 service A 里新增功能 X，影响 B/C"  | 拆分 + 多 worker 并行 + 综合    |
| 并行收集上下文       | "理解这个模块涉及哪些文件、有哪些约束" | multi_worker 并行 research      |
| 改 + 验 + 总结       | "改完之后跑测试，给我一份变更说明"     | review 性质任务 + artifact 沉淀 |
| 跨多 artifact 长任务 | "继续上次那个迁移任务"                 | trace + replay 可回看继续       |

## 5. 低优先级 / 不验证的任务类型

- 普通闲聊
- 轻量一次性问答
- 大企业审批流
- 高度标准化的客服流程
- 为展示而展示的多 agent 辩论秀

## 6. 用户旅程关键时刻

第一阶段我们重点优化以下时刻的体验：

1. **首次安装** → 5 分钟内能跑出第一次 OrchestrationRun
2. **首次失败** → 能清晰看到失败发生在哪一层（编排 / 任务 / 执行 / 产物）
3. **首次接管** → operator 能在 run 跑到一半时介入并继续
4. **回头继续** → 一周后回来，能找到上次的 run 并继续
5. **数据迁移** → 换机器时，能完整带走自己的数据
